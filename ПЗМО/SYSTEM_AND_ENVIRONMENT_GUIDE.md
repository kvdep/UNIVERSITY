### Проблема 1: Сбой C-драйвера NetCDF4 на путях с кириллицей в Windows
* **Симптом:** Ошибка C-библиотеки HDF5 / NetCDF: `[Errno -101] NetCDF: HDF error` или `No such file or directory`.
* **Причина:** C-библиотека NetCDF не поддерживает многобайтовые пути UTF-8 на платформе Windows.
* **Решение:** Преобразование пути в короткий формат Win32 (8.3) через вызов `kernel32.GetShortPathNameW`:
```python
import ctypes
import os
from ctypes import wintypes

def get_short_path(path: str) -> str:
    if os.name == 'nt' and os.path.exists(path):
        _fn = ctypes.windll.kernel32.GetShortPathNameW
        _fn.argtypes = [wintypes.LPCWSTR, wintypes.LPWSTR, wintypes.DWORD]
        _fn.restype = wintypes.DWORD
        buf = ctypes.create_unicode_buffer(0)
        needed = _fn(path, buf, 0)
        if needed > 0:
            buf = ctypes.create_unicode_buffer(needed)
            _fn(path, buf, needed)
            return buf.value
    return path
```

### Проблема 2: Заражение тензоров значениями NaN при маскированной арифметике
* **Симптом:** На итерации алгоритма невязка $\|R\|_F$ принимает значение `nan`, вычисления аварийно прерываются.
* **Причина:** По стандарту IEEE 754 произведение нуля на нечисловое значение дает нечисловое значение: $0.0 \times \text{NaN} = \text{NaN}$. Если входной массив содержит пропуски (`NaN`), любое матричное произведение с маской порождает `NaN`.
* **Решение:** Замена `NaN` на $0.0$ до начала тензорных операций с сохранением отдельной бинарной маски валидности:
```python
D_valid = torch.nan_to_num(D_tensor, nan=0.0)
valid_mask = torch.isfinite(D_tensor).float()

# Пример в итерационном процессе:
residual = (D_valid - L * valid_mask) * valid_mask
```

### Проблема 3: Зависание алгоритмов оптимизации при недостижимом пороге сходимости в float32
* **Симптом:** Число итераций достигает лимита `max_iter`, невязка стабилизируется около значения $8 \times 10^{-7}$.
* **Причина:** Машинный эпсилон одинарной точности IEEE 754 составляет $\epsilon \approx 1.19 \times 10^{-7}$. Погрешности округления при расчете сингулярных чисел делают относительный порог $\|R\|_F / \|D\|_F \le 10^{-7}$ недостижимым.
* **Решение:** Использовать порог сходимости $\text{tol} = 1.0 \times 10^{-5}$ для вычислений в типе `float32`.

### Проблема 4: Переполнение видеопамяти при вычислении SVD на крупномасштабных растрах
* **Симптом:** `torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 14.8 GiB...`
* **Причина:** Точное сингулярное разложение матрицы размера $M \times N$ требует создания унитарных матриц $U \in \mathbb{R}^{M \times M}$ и $V \in \mathbb{R}^{N \times N}$. При размерах свыше $3000 \times 3000$ объем выделяемой памяти превышает 14 ГБ.
* **Решение:** Пространственное блочное разбиение растра на тайлы размером $512 \times 512$ с шагом перемещения $448$ (перекрытие $64$ пикселя). Объем VRAM на один тайл составляет $\le 0.08$ ГБ.

### Проблема 5: Ступенчатые швы при сшивке перекрывающихся блоков
* **Симптом:** На картах градиентов видны скачки высоты на границах тайлов.
* **Причина:** Окно Ханна $w(x) = \sin^2(\pi x / B)$ формирует разбиение единицы ($\sum w = 1$) исключительно при перекрытии $50\%$ ($W_{\text{ov}} = B/2$). При меньшем перекрытии сумма весов в центральной зоне тайла отклоняется от 1.
* **Решение:** Применение двумерного кусочно-гладкого окна Тьюки:
```python
def tukey_window_2d(B: int, W_ov: int, device='cuda') -> torch.Tensor:
    x = torch.arange(B, dtype=torch.float32, device=device)
    w_1d = torch.ones(B, dtype=torch.float32, device=device)
    left = x < W_ov
    right = x >= (B - W_ov)
    w_1d[left] = torch.sin((torch.pi * (x[left] + 0.5)) / (2.0 * W_ov)) ** 2
    w_1d[right] = torch.cos((torch.pi * (x[right] - (B - W_ov) + 0.5)) / (2.0 * W_ov)) ** 2
    return torch.outer(w_1d, w_1d)
```

### Проблема 6: Зависание процессов и утечки видеопамяти при пакетной обработке
* **Симптом:** Процесс застревает в памяти, повторные запуски вызывают `CUDA out of memory`.
* **Причина:** Накопление графов автодифференцирования PyTorch в кэше аллокатора CUDA, отсутствие промежуточной очистки мусора.
* **Решение:**
1. Очистка кэша перед запуском вычислений и после каждого крупного блока:
```python
import gc
import torch

gc.collect()
if torch.cuda.is_available():
    torch.cuda.empty_cache()
    torch.cuda.ipc_collect()
```
2. Установка максимального времени выполнения одной задачи не более 20 минут.
3. Логирование прогресса обработки каждые $N$ блоков.

### Проблема 7: Утечка данных (Data Leakage) при расчете пространственных функций потерь
* **Симптом:** Оптимизационная модель минимизирует ошибку на отложенных валидационных узлах за счет захвата значений соседей.
* **Причина:** Применение сверточных ядер (фильтр Гаусса, операторы градиента) к маскированному полю невязок $e = y - \hat{y}$ до наложения обучающей маски $M_{\text{train}}$. Значения из тестовых ячеек попадают в рецептивное поле обучающих узлов.
* **Решение:** Применение предварительного маскирования с нормализованной сверткой (leak-free normalized convolution):
```python
import torch.nn.functional as F

e_masked = (y - y_hat) * m_train.float()
w_norm = F.conv2d(m_train.float(), kernel, padding=pad).clamp(min=1e-7)
e_smooth = F.conv2d(e_masked, kernel, padding=pad) / w_norm
```

### Проблема 8: Несоответствие шага вариационной регуляризации физическому масштабу данных
* **Симптом:** Вариационный алгоритм фильтрации (например, Total Variation) не изменяет входной массив, дисперсия извлеченного шума составляет менее $10^{-9}$.
* **Причина:** В схемах проекционного градиентного спуска (например, алгоритм Шамболля) шаг коррекции имеет вид $u = f - \alpha \operatorname{div}(p)$, где $\|\operatorname{div}(p)\| \le 4$. При $\alpha \sim 10^{-4}$ максимальное абсолютное смещение равно $4\alpha = 4 \times 10^{-4}$ единиц данных. Для данных с диапазоном значений $0 - 1000$ такое смещение численно пренебрежимо.
* **Решение:** Подбор параметра $\alpha$ с учетом физической дисперсии входного сигнала $\sigma^2$ и шага дискретизации: для диапазона значений в сотни единиц параметр регуляризации выбирается в интервале $\alpha \in [1.0; 5.0]$.

### Проблема 9: Разделение аппаратурного шума и структурного сигнала в эмпирической полувариограмме
* **Симптом:** Некорректная квалификация структурных вариаций рельефа как некоррелированного шума сенсора.
* **Причина:** Аппаратурный белый шум проявляется в экспериментальной полувариограмме исключительно как скачок в нуле — эффект самородков $c_0$ (nugget effect). Структурный порог $c$ (sill) и радиус корреляции $a$ (range) описывают пространственно зависимый автокоррелированный процесс.
* **Решение:** Модель сферической полувариограммы:
$$\gamma(h) = c_0 + c \left( \frac{3h}{2a} - \frac{h^3}{2a^3} \right), \quad h \le a$$
При фильтрации некоррелированного шума сенсора с дисперсией $\sigma_{\text{sensor}}^2$ проверяется критерий $c_0 \approx \sigma_{\text{sensor}}^2$, $c \to 0$, индекс Морана $I(e) \approx 0$. При $c_0 \approx 0$ и $c > 0$ извлеченный остаток представляет собой структурный сигнал, а не шум измерений.

### Проблема 10: Сбой кодировки консоли Windows cp1251 при выводе Unicode
* **Симптом:** `UnicodeEncodeError: 'charmap' codec can't encode character...` при выводе через `print()` в консоль Windows.
* **Причина:** Стандартный вывод `sys.stdout` в Windows инициализирован кодовой страницей `cp1251`, которая не содержит символов международной диакритики и математических обозначений.
* **Решение:** Принудительная реконфигурация потоков ввода-вывода в начале скриптов:
```python
import sys

if sys.platform == 'win32':
    if hasattr(sys.stdout, 'reconfigure'):
        sys.stdout.reconfigure(encoding='utf-8')
    if hasattr(sys.stderr, 'reconfigure'):
        sys.stderr.reconfigure(encoding='utf-8')
```

### Проблема 12: Рассинхронизация расчетного кода и контрольных точек (чекпоинтов)
* **Симптом:** Расчетный алгоритм модифицирован, но сохраненные результаты соответствуют предыдущей реализации.

* **Решение:** При изменении математических операторов или гиперпараметров обязателен полный перезапуск конвейера с очисткой устаревших файлов результатов (`.pt`, `.nc`, `.json`).

### Проблема 13: Недопустимость смещения критериев гипотез post-hoc (Goalpost Moving)
* **Симптом:** Критерии успешности гипотезы корректируются после завершения расчетов под фактически полученные числа.
* **Причина:** Стремление объявить гипотезу подтвержденной вопреки экспериментальным фактам.
* **Решение:** Предикаты подтверждения/отклонения гипотез фиксируются до начала расчетов. Если рассчитанная величина выходит за установленные границы, гипотеза признается строго отклоненной.

### Проблема 14: Недопустимость статического задания baseline-метрик
* **Симптом:** В таблицах сравнения результаты базовых методов зафиксированы константами без кода их воспроизведения.
* **Причина:** Отсутствие реального запуска сравниваемых алгоритмов.
* **Решение:** Каждый базовый метод сравнения должен быть реализован в кодовой базе и запущен на тех же входных данных с вычислением единого набора метрик.

После завершения процесса проверяется код возврата `$LASTEXITCODE == 0`, а статус сборки верифицируется по строке `Output written on ...` в выходном потоке.

### Проблема 22: Краевое искажение береговой линии при TV-фильтрации из-за заполнения NaN нулями
* **Симптом:** Прибрежные ячейки суши теряют десятки метров высоты, а вдоль береговой линии формируется зона ложной диффузии в морскую акваторию.
* **Причина:** Замена отсутствующих значений моря (`NaN`) на $0.0$ через `nan_to_num` перед градиентной TV-фильтрацией создает искусственный скачок высоты на береговой линии от высоты суши ($100-800$ м) до $0.0$ м. Оператор дивергенции $\operatorname{div}(p)$ формирует ложные потоки через границу суши.
* **Решение:** Изоляция краевых ячеек суши условиями Неймана на границе валидного носителя $\partial \Omega$:
```python
p_x = p[0] * valid_mask[:, :-1] * valid_mask[:, 1:]
p_y = p[1] * valid_mask[:-1, :] * valid_mask[1:, :]
```
Оператор дивергенции вычисляется только между смежными ячейками суши, исключая перенос высот через границу маски.

### Проблема 23: Систематическое усечение спектра в итерационном Randomized SVD при $r_k = k$
* **Симптом:** Относительная невязка низкоранговой компоненты $\|L^{\text{RSVD}} - L^{\text{Exact}}\|_F / \|L^{\text{Exact}}\|_F$ стабилизируется на высоком уровне ($8.8 \times 10^{-2}$), существенно превосходя допуск сходимости $10^{-5}$.
* **Причина:** Если на текущей итерации число сингулярных чисел, превышающих порог отсечения $\mu^{-1}$, достигает текущего размера рандомизированного базиса $k$ ($r_k = k$), отсекаются все последующие сингулярные числа, которые также превосходят порог $\mu^{-1}$, но не попали в проекцию ранга $k$.
* **Решение:** Контроль насыщения ранга внутри итерации: при $r_k = k$ текущий шаг SVT обязан немедленно перезапускаться с увеличенным размером проекции $k_{\text{new}} = \min(2k, \min(m, n))$, исключая фиксацию усеченного спектра.

### Проблема 26: Математическая инверсия весовой функции пространственной адаптации регуляризации (SARP)
* **Симптом:** Вариационный алгоритм фильтрации срезает острые горные хребты и оставляет зашумленными выположенные равнины.
* **Причина:** Использование экспоненциально убывающей весовой функции привязки $\lambda = \lambda_0 \exp(-\gamma \cdot s)$. При $s \to \infty$ штраф привязки к данным $\frac{\lambda}{2}(u - \hat{f})^2$ стремится к 0, уничтожая горные хребты.
* **Решение:** Применение строго монотонно возрастающей аддитивно-нелинейной композиции уклона и отрицательной главной кривизны Гессиана:
$$\lambda_{i,j} = \lambda_{\min} + (\lambda_{\max} - \lambda_{\min}) \cdot \left( 1 - \exp\left( -\gamma \cdot s_{i,j} - \beta \cdot \frac{c_{i,j}^+}{c_{\text{norm}}} \right) \right)$$
где $s_{i,j} = \min(1.0, \|\nabla_{\text{metric}} \hat{f}_{i,j}\|_2 / \tan(60^\circ))$, $c_{i,j}^+ = \max(0, -\kappa_{\min, i,j})$.

### Проблема 31: cuSOLVER fallback при точном SVD на GPU для граничных и маскированных матриц в PyTorch
* **Симптом:** Предупреждение `UserWarning: torch.linalg.svd: During SVD computation with the selected cusolver driver, batches 0 failed to converge. A more accurate method will be used to compute the SVD as a fallback.` и резкое падение производительности вычисления (с 25 мс до сотен миллисекунд или секунд на матрицу).
* **Причина:** В драйвере CUDA cuSOLVER стандартный итерационный алгоритм Якоби `gesvdj` / `gesvda` не сходится на плохо обусловленных матрицах с резкими скачками ранга и большими областями нулевого дополнения (маскированная морская акватория или паддинг границ сцены). PyTorch переключается на точный QR-алгоритм `gesvd`.
* **Решение:** При обработке сплошной сцены с большим числом береговых тайлов для ускорения итерационных циклов IALM использовать Adaptive RSVD с динамическим рангом, либо при использовании точного SVD учитывать временной бюджет (~30 с на тайл с fallback).

### Проблема 33: Рассинхронизация нумерации, порядка и графического содержания рисунков в статьях

### Проблема 34: Интерпретация погрешностей фильтрации ЦМР: RMSE, систематическое смещение датума и среднеквадратическое отклонение
* **Симптом:** Непонимание физического смысла метрик ошибок: почему модели со спектральным коллапсом (U-Net H1/H2) имеют $\text{RMSE} \approx \sigma_z = 154{,}88$~м, почему у модели без датумной привязки (H4) накапливается систематический высотный сдвиг $\bar{e} = -2{,}93$~м, а у переобученной непрерывной модели (H8) стандартное отклонение $\sigma(e) = 5{,}91$~м оказывается ниже паспортного шума сенсора ($\approx 6{,}8 - 9{,}7$~м).
* **Причина:** Ошибочное отождествление среднеквадратической ошибки $\text{RMSE}$ со среднеквадратическим отклонением случайной величины $\sigma(e)$ без учета систематического сдвига датума $\bar{e}$.
* **Решение:** Использовать строгое математическое разложение погрешности:
$$\text{RMSE}^2 = \sigma(e)^2 + \bar{e}^2,$$
где $\bar{e} = \frac{1}{N} \sum_{i=1}^N (y_i - \hat{y}_i)$~--- систематический высотный сдвиг опорного геодезического датума, а $\sigma(e) = \sqrt{\frac{1}{N} \sum_{i=1}^N (e_i - \bar{e})^2}$~--- среднеквадратическое отклонение случайной компоненты невязок.
* Если модель коллапсирует в плоскую константу $\hat{y} \equiv \bar{y}$ (как H1/H2), то $\bar{e} \approx 0$, а $\sigma(e) \approx \sigma_z = 154{,}88$~м (невязка равна дисперсии самого природного рельефа полигона, а не шума).
* Если модель не имеет свободного члена датума (H4), она дает смещение $\bar{e} = -2{,}93$~м.
* Если модель улавливает правильный датум ($\bar{e} \approx 0$) и фильтрует спекл-шум сенсора, ее $\sigma(e) \approx 14{,}52$~м согласуется с паспортным доверительным интервалом $\text{LE90} = 16{,}0$~м ($\sigma_{\text{sensor}} \approx 9{,}73$~м на равнинах и до $15-20$~м на горных склонах).
* Если модель сглаживает естественный микрорельеф и переобучается (H8), ее $\sigma(e) = 5{,}91$~м падает ниже физического шума сенсора, уничтожая природные морфоструктуры.

### Проблема 35: Ложное срабатывание детектора маскировки заимствований в системе «Антиплагиат» из-за генерации растровых шрифтов Type 3 в pdfTeX
* **Симптом:** Система «Антиплагиат.ВУЗ» помечает загруженный PDF красным предупреждением: `Внимание, документ подозрительный: обнаружены попытки маскировки заимствований`, рассчитывая оригинальность $98-99\%$ при минимальном объеме совпадений ($1\%$).
* **Причина:** Компиляция русскоязычного документа `pdflatex` без векторных шрифтов `cm-super` или пакета `cmap`. Сборщик генерирует растровые шрифты Type 3 (`.pk`), у которых отсутствует таблица перекодировки `/ToUnicode`, а глифы названы произвольными именами `/a224`, `/a207`, отсутствующими в спецификации Adobe Glyph List. По стандарту ISO 32000-1 парсеры PDF отображают байты некодированного шрифта в диапазон Latin-1 (`0x80..0xFF`). В извлеченном тексте доля кириллицы составляет $0{,}00\%$, а русский текст превращается в моджибаке («Ïðîñòðàíñòâåííî...»). Детектор безопасности «Антиплагиата» классифицирует расхождение визуального рендера и текстового слоя как попытку умышленной подмены символов.
* **Решение:** Обеспечить использование векторных Type 1 шрифтов `cm-super` (`sfbx*.pfb`, `sfrm*.pfb`) с вектором `cm-super-t2a.enc`. Проверять текстовый слой PDF через `PyMuPDF`: доля символов кириллицы `U+0400`..`U+04FF` обязана превышать $55\%$, а символов Latin-1 High — быть менее $1\%$.

### Проблема 38: Генерация лишней пустой страницы при переходе на альбомную ориентацию `newgeometry` с таблицами `tabularx`
* **Симптом:** В скомпилированном PDF-документе перед таблицей `tabularx` появляется пустая страница с единственным номером, а сама таблица выносится на следующую страницу.
